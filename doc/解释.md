# 启动 1 个线程，mmap 映射方式，对`/tmp/testfile`做4KB 块随机读压力测试，持续跑满 20 秒。

fio --name=mmap-randread --filename=/tmp/testfile --rw=randread --bs=4k --size=1G --ioengine=mmap --numjobs=1 --runtime=20 --time_based

参数含义:
--name=mmap-randread	任务名字，输出报告里显示的 job 名称，自定义
--filename=/tmp/testfile	被测文件路径，就是 dd 生成的 1GB 测试文件
--rw=randread	读写模式：randread = 随机读；其他可选：read 顺序读、write 顺序写、randwrite 随机写、rw 混合读写
--bs=4k	block‑size，IO 块大小，每次发起 4KB 读请求。数据库、RocksDB 典型的随机 IO 就是 4K。
--size=1G	测试文件逻辑大小 1G；代表会在 0~1G 范围内随机找偏移读。
--ioengine=mmap	IO 引擎：使用 mmap 内存映射方式访问文件；把文件映射进进程虚拟地址空间，用内存访问触发磁盘 IO。⚠️区别常用的libaio（Linux 异步 IO）；mmap 走 page cache。
--numjobs=1	并发 job 线程数，这里单线程；numjobs=8 就是 8 个线程并发压测。
--runtime=20	测试持续运行20 秒
--time_based	时间模式：哪怕提前读完整个 1G 文件，也继续循环随机读，跑满 20 秒才结束。不加 time_based：读完 size=1G 就直接退出，跑不满 20s。
----

1. **`IOPS=2281`**
每秒完成 2281 次 4KB 随机读。
> 4K 随机读 IOPS 是 SSD 核心指标；机械盘 HDD 通常只有一两百 IOPS。

2. **`BW=9125KiB/s`**
读带宽 ≈ 8.9MB/s。
> IOPS × bs = 2281 ×4K ≈ 8.9MB/s，互相印证。

3. **`clat (usec)` completion latency**
> **clat = 从 IO 请求提交完成，到返回结果的完成延迟（微秒），业务最关心！**
- `min=176us`：最小延迟 176 微秒
- `avg=435us`：平均延迟 435 微秒
- `max=57819us`：最大延迟 57ms（出现毛刺、尾延迟）
- `stdev=705`：标准差很大，说明延迟抖动很厉害。

4. **percentiles 分位数（重中之重，存储、数据库必看 P95/P99/P99.9）**
- P50=347us：一半请求耗时小于 347 微秒
- P95=685us：95% 请求 ≤685us
- **P99=1958us（1.9ms）**：1% 请求超过 1.9ms
- **P99.9=10028us（10ms）**：千分之一请求大于 10ms，这就是尾延迟！
> 数据库、LSM 引擎最怕 P999、P9999 毛刺，哪怕平均延迟很好，少量慢请求会拖垮上层业务。

5. `cpu: usr=1.47%, sys=4.94%`
CPU 占用不高；mmap 模式，sys 是内核态开销。`majf=45628`：**主缺页中断 45628 次**。mmap 发生 page fault，触发从磁盘加载 page 到内存。minf 次要缺页很少。

6. `Disk stats sdd util=90.05%`
磁盘`sdd`设备，**磁盘繁忙度 util=90.05%**，磁盘几乎跑满。
